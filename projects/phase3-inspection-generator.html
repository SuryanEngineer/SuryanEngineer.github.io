Phase 3 Inspection Generator

Developed a geospatial matching system that identifies eligible training inspections for each trainee inspector, prioritizing nearby opportunities and applying a priority-aware travel fallback when local options are unavailable. The system saves approximately three hours of manual work per day.

Python Geospatial Matching Automation Excel

The Problem

Training-inspection matching required manual research

New inspectors need supervised, qualifying inspections to complete Phase 3 of their training — but not every inspection qualifies, and not every qualifying one is near a given trainee. Before this system, someone had to manually filter the full inspection list down to what actually counted for Phase 3, cross-reference it against where every trainee was based, and work out by hand which nearby inspections each trainee could realistically attend, then resolve the messier cases where a trainee had nothing close by and needed to travel instead.

The Approach

Reducing a large inspection dataset to actionable candidate lists

I built a tool that filters the inspection data down to what's actually eligible for Phase 3 training, maps every trainee and eligible inspection geographically, and generates a candidate list for each trainee — nearby options first, with a travel fallback only when nothing local exists.

Filter eligible inspections → Map trainees & inspections → Match nearby options → Resolve travel fallback → Candidate list per trainee

Technical Implementation

How it works

  • Eligibility filtering: narrows the full inspection dataset down to just the ones that qualify as Phase 3 training inspections, before location even enters the picture.
  • Geospatial mapping: every trainee and every eligible inspection is geocoded and placed on the same map, so proximity between the two can be computed directly instead of estimated by hand.
  • Nearby matching: for each trainee, the system finds eligible inspections within a reasonable distance, applying the constraints specific to that trainee so the list is realistic, not just geographically close.
  • Travel fallback with a priority rule: when a trainee has nothing nearby, the system looks at eligible inspections they could travel to — but skips any inspection that another trainee is already positioned closer to, since that trainee has first claim on it. This keeps two trainees from being pointed at the same distant inspection when only one of them actually needs to travel for it.
  • Output: a filtered candidate list per trainee, ready for whoever schedules the next training inspection to review and confirm.

Results

Impact

What used to be a manual cross-referencing exercise — filtering eligibility, checking locations, and working out travel cases by hand — now runs automatically and produces a short, ready-to-review list. The system is estimated to save approximately three hours of work per day for the person who previously ran this process manually.

Engineering Lessons

Reflections

  • Geospatial reasoning requires explicit distance definitions. This was the first project I'd built that had to reason about real-world location rather than categorical data. Implementing the Haversine formula to calculate distance between two coordinates, rather than treating it as a solved problem, established a consistent basis for evaluating geographic proximity and became a foundation for every geospatial project I built after this one.
  • Nearest-neighbor matching becomes more complex when shared priorities are introduced. The hard part wasn't finding the closest eligible inspection for a trainee — it was ensuring a travel fallback for one trainee never took priority away from another trainee with a stronger geographic claim to the same inspection.
  • Eligibility rules require domain validation. Filtering on inspection type alone missed real cases that mattered, so the initial filtering criteria had to be refined through discussions with the process owner to capture cases that couldn't be inferred reliably from the underlying inspection fields alone.
  • Automation doesn't need to replace human judgment to create significant value. Narrowing a large, tedious search down to a short, relevant candidate list was sufficient to eliminate most of the manual effort while preserving human oversight of the final decision.
