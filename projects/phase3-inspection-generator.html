Phase 3 Inspection Generator

A geospatial matching tool that finds eligible training inspections for each trainee inspector — falling back to travel-eligible options only when a closer trainee doesn't already have priority on them — saving an estimated 3 hours of work a day for the person who used to do this by hand.

Python Geospatial Matching Automation Excel

The Problem

Matching trainees to training inspections was a manual research task

New inspectors need supervised, qualifying inspections to complete Phase 3 of their training — but not every inspection qualifies, and not every qualifying one is anywhere near a given trainee. Before this system, someone had to manually filter the full inspection list down to what actually counted for Phase 3, cross-reference it against where every trainee was based, and work out by hand which nearby inspections each trainee could realistically attend — then figure out the messier cases where a trainee had nothing close by and needed to travel instead.

The Approach

From a full inspection list to a short list per trainee

I built a tool that filters the inspection data down to what's actually eligible for Phase 3 training, maps every trainee and eligible inspection geographically, and generates a candidate list for each trainee — nearby options first, with a travel fallback only when nothing local exists.

Filter eligible inspections → Map trainees & inspections → Match nearby options → Resolve travel fallback → Candidate list per trainee

Technical Implementation

How it works

  • Eligibility filtering: narrows the full inspection dataset down to just the ones that qualify as Phase 3 training inspections, before location even enters the picture.
  • Geospatial mapping: every trainee and every eligible inspection is geocoded and placed on the same map, so proximity between the two can be computed directly instead of estimated by hand.
  • Nearby matching: for each trainee, the system finds eligible inspections within a reasonable distance, applying the constraints specific to that trainee so the list is realistic, not just geographically close.
  • Travel fallback with a priority rule: when a trainee has nothing nearby, the system looks at eligible inspections they could travel to — but skips any inspection that another trainee is already positioned closer to, since that trainee has first claim on it. This keeps two trainees from being pointed at the same distant inspection when only one of them actually needs to travel for it.
  • Output: a filtered candidate list per trainee, ready for whoever schedules the next training inspection to review and confirm.

Results

Impact

What used to be a manual cross-referencing exercise — filtering eligibility, checking locations, and working out travel cases by hand — now runs automatically and hands back a short, ready-to-review list. It's estimated to save around 3 hours of work a day for the person who used to run this process manually.

What I Learned

Reflections

  • This was the first project I'd built that had to reason about real-world location rather than categorical data, and it meant actually learning how to calculate distance between two coordinates — the Haversine formula — instead of treating it as a solved problem. That groundwork carried directly into every geospatial project I built after this one.
  • Nearest-neighbor matching sounds like a solved problem until a fairness rule gets added on top. The hard part here wasn't finding the closest eligible inspection for a trainee — it was making sure a travel fallback for one trainee never quietly took priority away from another trainee it actually belonged to.
  • "Eligible for Phase 3 training" turned out to be a fuzzier rule than it first sounded. Filtering on inspection type alone missed real cases that mattered, so getting the eligibility rule right took as much back-and-forth with the person who ran this by hand as the matching logic did.
  • The tool doesn't need to make the final call to save real time. Narrowing a large, tedious search down to a short list a person can glance at and confirm turned out to be exactly the amount of automation this process actually needed.
