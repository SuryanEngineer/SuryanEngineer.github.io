NSPIRE Candidate Finder

Developed an automated recruiting pipeline that searches target markets for certified home inspectors, extracts candidate information, evaluates candidate fit using LLMs, and produces a ranked dataset for recruiter review.

Python AI / LLMs Automation Excel Data Deduplication Tool Design

The Problem

Manual directory searching doesn't scale

Recruiting inspectors required manually searching certification directories one market at a time, reviewing individual listings, and judging whether a candidate was worth reaching out to. As the candidate list grew into the hundreds, repeated searches also produced duplicate candidates and inconsistent coverage across markets — and none of it scaled past a handful of markets at a time.

The Approach

A search-and-review process that runs on its own

I developed a pipeline that automates the search, extraction, evaluation, deduplication, and reporting stages of the process. Searches are executed against defined target markets, candidate information is extracted from public pages, an LLM evaluates fit against specified criteria, and results are consolidated into a ranked Excel output for recruiter review.

Search markets → Find candidate pages → Pull out the details → AI reviews & scores fit → Ranked Excel spreadsheet

Technical Implementation

How it works

  • Searches each target market using a consistent, repeatable set of search terms, so coverage is predictable instead of random.
  • Reads each candidate's page and extracts the details that matter — current role, employer, certification, experience — automatically.
  • Uses an LLM to evaluate candidate fit against a defined scoring framework and generate a concise rationale for each result, the same way a recruiter would jot down first impressions.
  • Automatically recognizes when the same person shows up more than once (even under a slightly different listing) and combines them into one record instead of creating a duplicate.
  • Search execution is structured to maximize coverage while respecting the limits of the underlying services.
  • Outputs everything into a polished, color-coded Excel file that's ready to hand off — no cleanup needed.
  • Packaged the whole thing as a simple double-click program for coworkers with no technical background, so anyone could run a search or refresh the spreadsheet without installing anything or touching a command line.

Results

Impact

What used to be manual, one-market-at-a-time searching now runs unattended. During its first day of production use, the system identified more than 130 candidates across eight target markets.

Engineering Lessons

Reflections

  • Designing for non-technical users is its own engineering problem. A command-line flag made sense to me, but the right interface for someone who'd never open a terminal turned out to be one simple question asked out loud when the program starts — this took more iteration than the search logic itself.
  • A fit score is only useful if a recruiter can tell whether to trust it. Having the LLM write a short rationale alongside every score, the same way a person would jot down a first impression, mattered more for actual adoption than making the scoring itself more sophisticated.
  • Shipping a known-working version beats gambling on an untested one. Right before a deadline, I identified a change I could make quickly but couldn't safely test in time — I shipped the version that already worked and saved the improvement for the next round.
